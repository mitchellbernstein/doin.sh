# Web account and billing

The browser account page is served directly by the existing Worker at `https://sync.doin.sh/account`. The marketing site's Account link and iOS Manage on doin.sh can lead there without transferring a native bearer. Email account creation/sign-in uses the existing `/v1/auth/start` and `/v1/auth/poll` proof flow. The page creates 32 cryptographically random bytes, computes SHA-256 S256 proof, displays the independent confirmation code, polls within the ten-minute expiry and keeps its own browser bearer in sessionStorage (memory fallback). Sign-out revokes the browser session. No authentication or Stripe API contract changed.

Billing reads current server entitlement. Free accounts can buy doinMORE only through explicit browser Checkout, monthly/yearly. Active subscriptions show renewal/end date with explicit cancel/resume actions. Buttons lock during mutations; checkout destinations require HTTPS, checkout.stripe.com, no credentials and no alternate port. All account assets use no-store, no-referrer, nosniff and strict same-origin script/style/connect policy; DOM account data uses textContent. Existing emailed verification forms retain strict-origin for their exact-origin POST validation.

No framework added. Target is the existing Workers compatibility environment and Wrangler 4.147.0. Latest primary documentation read before implementation: [Cloudflare Response](https://developers.cloudflare.com/workers/runtime-apis/response/), [W3C Web Crypto random values and digest](https://www.w3.org/TR/webcrypto/). Existing email, D1 and Stripe protocol details were read in docs/sync.md and cloud/worker.ts.
