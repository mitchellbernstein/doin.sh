# Independent folder review

Reviewed 2026-10-03: cloud/folders.ts, migration 0007, local folders, and team folder integration. Read-only review; no build, runtime or database was started while the Windows lane held the shared command budget. Findings below distinguish source fixes from pending E2E verification.

## Findings

1. **P1 — Personal library siblings could be linked and uploaded as team files.** Original `src/team.zig:88-95` checked only `config.storage`. With `library_root=/library` and `storage=/library/Projects`, `/library/Personal` passed that guard. Selecting a different personal folder later also changed the protected subtree. Configuration read failures were swallowed. Owner fixed `src/team.zig:87-105` to check canonical storage and library root at link/push/pull and propagate errors other than missing configuration. New native regressions are written; runtime verification remains pending.

2. **P1 — Offboarding could be undone with an older unconsumed invitation.** Original `cloud/team.ts:107-111` removed membership but retained invitations addressed to the departing verified email. `/accept` could recreate membership and folder grants using a valid owner-issued token. Owner fixed `cloud/team.ts:107-114` with transactional invitation cleanup plus member removal, and added account-deletion invitation cleanup in migration 0005. A removed-member token-rejoin regression is written; runtime verification remains pending. This matches the documented immediate revocation of pending invitations.

3. **P2 — A replaced canonical team directory could silently redirect sync.** Original `src/team.zig:264-266` realpathed the saved folder and accepted a different result. Move the originally linked directory and replace its old pathname with an alias to another directory: push/pull targeted that new directory. Owner now rejects canonical path changes at `src/team.zig:269-275`, with Windows case-insensitive comparison. A parent-alias regression is written; runtime verification remains pending.

4. **P2 — Stored local library root has the same alias-replacement boundary.** `src/folders.zig:43-45` canonicalizes the supplied root, and `src/main.zig:799` canonicalizes the stored `library_root` before calling it. A replaced stored root therefore becomes a different library without an identity check. Child/file symlink refusal does not cover this root remapping. Sent to local-folder/onboarding owners: reject changed canonical stored-root paths or bind the stored library to its stable root identity. Initial explicit root selection may still resolve an alias. Status: main owner added canonical stored-root checks before folder commands and personal library sync; Windows case-fold equality adjustment is in progress. Runtime alias regression is included in the library fixture.

5. **P1 — Personal paid sync addresses one selected document, not the library tree.** `Config` now separates `library_root` from `storage`, but `src/sync.zig:412-454` still sends the selected folder to `/v1/document`, and the backend keys that document only by account. Multiple local folders cannot independently sync contents, IDs, hierarchy or renames. Existing conflict/precondition guards help preserve bytes; they do not supply hierarchy sync. Root assigned a personal-folder service/native implementation to close this gap.

## Checks that hold at source level

Team folder reads derive current membership and inherited grants in the document query. Document mutation repeats current inherited write permission, team entitlement and expected revision in one SQL update (`cloud/folders.ts:18-23`); an earlier successful ACL read cannot authorize a later revoked write. OAuth mutations additionally check the live scoped grant. Parent IDs and grants are constrained within the team by composite foreign keys. Move SQL computes descendants and repeats management authority while comparing the observed parent/name, preventing a member move or a direct cycle. Grant removal is additive: another ancestor grant can still authorize access, as documented. Owners/admins have global folder access; narrow invitations do not confer that role without the explicit admin acknowledgment. Visible lists redact inaccessible parent IDs. Recursive UNION and a 4,096-node limit avoid unbounded repeated cycle traversal.

Migration 0007 preserves existing root content/revision and gives existing members their previous root write access; new invitations explicitly select a subtree and read/write scope. Root document compatibility routes now read/write the new root folder, rather than a stale second document table.

Primary infrastructure references checked during review: [D1 foreign keys](https://developers.cloudflare.com/d1/sql-api/foreign-keys/) confirms enforcement in queries/migrations and cascading behavior; [D1 database API](https://developers.cloudflare.com/d1/worker-api/d1-database/) documents ordered transactional batches. Runtime E2E still needs to prove the concrete revocation and race cases against workerd/D1.

## Minimal personal hierarchy design

Use account-scoped personal folders with stable IDs, parent/name metadata and per-document revisions, plus one account library tree revision. Migrate the existing account document to the root compatibility node. Keep `/v1/document` as root-only compatibility; new clients use `/v1/folders` and `/v1/folders/ID/document`. Server ownership always derives from the device session, never a client account ID.

A full metadata snapshot must be bounded, rooted, connected, acyclic and unique by sibling name. Tree writes require the exact tree revision; document writes require the exact folder revision. Omitted folders must not erase their document bytes or silently authorize local deletion. Preserve remote nodes/tombstones and require an explicit decision for structural conflicts. Native whole-library sync binds the canonical library root and its identity, maps the portable root ID to the cloud compatibility root, and maintains per-folder content baselines. First link cannot overwrite divergent cloud/local content. Renames and moves retain IDs. Download cannot follow aliases, replace unmanaged directories, or overwrite a concurrently edited local document. Conflict artifacts contain both metadata snapshots and relevant Markdown.

Failure scenarios required before implementation: two devices creating different subtrees; concurrent rename/move and document edits; root/deep-node conflicts; unknown or duplicate IDs; disconnected/cyclic trees; invalid path components and sibling collisions; symlink/junction replacement; local external edits during provider I/O; partial push/pull interrupted before baseline persistence; expired auth/entitlement; remote omissions/tombstones; stale pinned job storage; legacy root compatibility; documents on untouched siblings remain unchanged. No implicit delete and no last-write-wins.

Implementation follow-up: personal library backend and native source now include full-tree/per-folder CAS, account credential pinning, portable materialization preflight, private conflict snapshots and explicit document-only resolution. Native runtime verification is pending the parent-owned serial build/E2E lane.
