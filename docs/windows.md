# Windows port checkpoint

Failure census before execution: redirected pipes must remain plain; failed console activation must restore both original modes and UTF-8 code page; raw keys, paste, Unicode and resize must survive; Ctrl+C must restore the footer and terminate only owned children; suspended child setup errors must reap the child; a killed job must include grandchildren; full stdout/stderr pipes must not deadlock; invalid UTF-8 paths/URLs and browser refusal must fail visibly; private credential files must reject inherited/public ACLs; installers must reject checksum mismatches and preserve existing binaries; unsupported notification scheduling must never pretend to be enabled.

The platform adapter keeps ANSI rendering outside OS APIs. Windows uses console modes, native job objects and file DACLs. ConPTY E2E on a real Windows runner is required before claiming support. A cross-compile alone is insufficient.

Primary references: [console modes](https://learn.microsoft.com/en-us/windows/console/setconsolemode), [ConPTY hosting](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session), [job objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects), [pipe availability](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-peeknamedpipe), [browser opening](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecutew).

The source now includes a PowerShell checksum-verifying installer and Windows x64 archive. Windows CI runs the actual native binary for Unicode/spaced paths, completion/undo, protected configuration ACLs, local client/server MCP interoperability, and a real ConPTY keyboard/resize/exit recording. Task Scheduler registration is isolated and deleted in a finally block; the fixture deliberately has no due reminder. Test results and raw terminal output are retained in `artifacts/windows-e2e`. These checks are not yet reported as passed.

`DOIN_BROWSER_COMMAND` optionally chooses an executable to receive one URL argument, with no shell evaluation; otherwise Windows uses ShellExecuteW. Browser error fallback keeps the valid URL visible.

Private file setup sets the current token user as owner and installs a protected DACL with one full-access ACE for that SID before secret bytes are written. Reads reject public/inherited ACLs. Administrators retain their OS privilege boundary, as root does on Unix. The compact stdio loop uses bounded chunks with anonymous-pipe nonblocking mode and availability checks rather than adding an asynchronous runtime. [Pipe mode documentation](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-setnamedpipehandlestate), [file security API](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-setnamedsecurityinfow), [hosted Windows runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).

Actual checkpoint CI exposed three harness gaps before platform acceptance: PowerShell split unquoted Zig module arguments; a cp1252 artifact write discarded the Unicode receipts; the installer download shim's script-scoped archive variable collided with the production installer's temporary archive variable. The next real runner must retain UTF-8 receipts, stop immediately on each failed native command, and bind immutable fixture paths through an explicit closure. No Windows runtime pass is claimed yet.

Primary PowerShell guidance: [argument parsing](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_parsing?view=powershell-7.5), [scope](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_scopes?view=powershell-7.5), [captured closures](https://learn.microsoft.com/en-us/dotnet/api/system.management.automation.scriptblock.getnewclosure?view=powershellsdk-7.4.0).

The next actual runner checkpoint also diagnoses console hosting separately: a native `cmd.exe` output probe runs through the same ConPTY before the TUI, output is drained before process creation, and creation-side handles close only after the hosted process attaches. Timeout receipts include the child's exit status. This follows [Microsoft's ConPTY lifecycle guidance](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session). ACL checks retain PowerShell diagnostics and protected-rule counts; they do not weaken the single-current-user rule requirement. Actual Windows guidance checks exercise missing-only AGENTS creation, update cancellation and preservation of user rules without symlink assumptions.

Actual runner 37165946507 identified the remaining harness causes: Windows PowerShell 5 inherited PowerShell 7 module paths, and redirected CI standard handles escaped into the ConPTY child. ACL verification now uses the runner's `pwsh`; ConPTY uses `STARTF_USESTDHANDLES` with null standard handles to request pseudoconsole connections, following the [Microsoft Terminal maintainers' documented redirected-host fix](https://github.com/microsoft/terminal/discussions/15814) and [current connection implementation](https://github.com/microsoft/terminal/blob/main/src/cascadia/TerminalConnection/ConptyConnection.cpp). Actual Task Scheduler rejected the previous XML encoding; its owner changed serialization to BOM-prefixed UTF-16LE with matching declaration, and the fixture checks the BOM and decodes UTF-16. These fixes still require the next real runtime gate.

Run 37166463372 passed native ACL, scheduler and all console interactions; its final assertion incorrectly required an exact Unix DECSTBM reset sequence from ConPTY's rendered stream. The replacement attaches a native probe before and after doin to the same pseudoconsole, records input/output console modes and output codepage, verifies cursor visibility, and advances from row one past the viewport height to prove scrolling reaches the full bottom row. The recorded bracketed-paste state must end disabled. This checks actual restoration rather than a byte-preserving transport assumption; [Microsoft documents the pseudoconsole translation boundary](https://learn.microsoft.com/en-us/windows/console/pseudoconsoles). The next Windows gate must still pass before support is claimed.

Actual run 37166729954 passed all eight native Windows groups, including console state restoration. Its installer update exposed PowerShell converting `$null` to an empty backup path. The atomic `File.Replace` call now uses PowerShell's explicit NullString singleton so .NET receives a genuine null backup path; first install, refusal, checksum preservation and explicit replacement remain covered by the existing real archive fixture. See [NullString](https://learn.microsoft.com/en-us/dotnet/api/system.management.automation.language.nullstring?view=powershellsdk-7.4.0) and [.NET File.Replace](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.replace?view=net-9.0). Final installer acceptance is pending the next runner.
