# Guidance for external agents

Primary guidance inspected2026-10-03: [OpenAI AGENTS.md discovery](https://learn.chatgpt.com/docs/agent-configuration/agents-md) reads at most one instruction file per directory and combines project-root to current-directory guidance. Outside a detected project root it checks the current directory. AGENTS.override.md takes precedence. [Claude Code project memory](https://code.claude.com/docs/en/memory) documents current native AGENTS.md fallback, its interaction with existing CLAUDE.md files, and `@AGENTS.md` imports. AGENTS support depends on Claude version/configuration. A portable optional CLAUDE.md import avoids relying on every session's fallback behavior. No agent execution/consent is claimed by file generation.

Commands: `agents status`, `agents init`, `agents update [--claude] [--yes]`. New-library onboarding creates missing AGENTS.md by default, without another question. Existing configurations stay opt-in through agents init; Simple onboarding adds no new prompt. Init/automatic folder creation creates only absent AGENTS.md, never edits existing files. The CLAUDE.md import is optional through explicit update --claude. Update proposes a bounded managed block, preserving all user content around it; existing content changes require an explicit preview/approval. Users can edit the files themselves. Updates intentionally regenerate the managed block after approval, so keep lasting personal additions outside its markers.

Root and selected-folder AGENTS.md are self-contained. Subfolder files use local relative tasks.md references and generic library protocols, without memberships, credentials, absolute machine paths, or invented permissions. Native Codex root inheritance cannot be assumed for a Markdown library outside a Git project; local folder guidance remains useful there. Deeper guidance and user overrides may refine instructions but cannot grant server access.

Generated text covers checkboxes and statuses, fenced examples, schema/task value JSON comments, stable property/option/task/reminder IDs, calendar/reminder semantics, preserving unknown Markdown, rereading current bytes before changes, user-reviewed destructive changes, and MCP read/revision/explicit-confirmation CAS. Team access is checked by the server; assignee labels and local instruction files do not confer write permission.

E2E fixture was written before the isolated module and produces `artifacts/agent-guidance-e2e/report.json` plus generated sample files. Native source and integration verified2026-10-03: six real-CLI E2E groups passed with18 recorded commands. Includes new-library defaults, existing-file preservation and reviewed updates, fenced marker examples, new-folder guidance, legacy-config opt-in, stale external edits, symlink refusal and malformed-block protection. Hosted/local MCP verification belongs to the MCP integration receipt.

Native and hosted/local MCP share src/agent_protocol.json. Transport-specific MCP context adds selected scope and tool-revision requirements without duplicating the Markdown protocol. File generation does not sync customized guidance across devices, and cloud tool guidance does not pretend to read local user AGENTS.md.

Managed updates commit each file atomically after a fresh-byte comparison. A later concurrent edit can stop remaining files after an earlier approved file was updated; review current files before retrying. Preflight checks all planned files before the first write, and automatic creation never follows or overwrites an existing file.
