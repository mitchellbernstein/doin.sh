# Inline terminal interface

## Failure scenarios and acceptance plan (before implementation)

The current prompt has no editable composer, no visual hierarchy, no persistent model/storage context, and treats everyday language as unknown commands. The replacement must handle small terminals and long paths/tasks; UTF-8 editing without splitting code points; cursor/delete/backspace/home/end; history without overwriting the current draft; bracketed paste without accidental submission; Ctrl+C/Ctrl+D/SIGTERM without leaving raw mode or a hidden cursor; terminal resize without destructive clearing; no alternate screen or scrollback erasure; provider failures without a lost task file; preview rejection without a write; model output containing terminal controls; first-run onboarding in location-then-model order; NO_COLOR/TERM=dumb/piped output without ANSI; and unchanged existing CLI/script commands.

The black-box PTY harness will exercise realistic Markdown containing sections, nested tasks, completed tasks, long titles, café/CJK/emoji text, and fenced examples. It will type/edit/recall commands through a real pseudo-terminal, verify resulting Markdown, use a real local fixture HTTP server for natural-language questions and generated-content preview, reject and accept previews, resize the terminal, inspect termios restoration after keyboard/signal exit, and save raw terminal transcripts, readable screen captures, terminal sizes, binary hash, requests, and outcomes. Provider fixtures do not establish live ChatGPT consent or inference.

## Design contract

Use the normal terminal screen and scrollback. Print a readable task board and conversation results above a framed, editable composer. Repaint only the active composer, never erase the screen/history. Use default terminal foreground for body text, neutral gray borders and muted system hints, bold headings, spacing, wrapped tasks, meaningful section/nesting structure, task counts, and model/storage context. Slash commands remain discoverable through hints and /help. A narrow window keeps input and essential hints readable before decoration. NO_COLOR, TERM=dumb, and redirected output remain plain.

Keyboard editing supports arrows, Home/End, Delete/Backspace, Ctrl+A/E/U/K/W, history, Tab command completion, and bracketed paste. Ctrl+C or Ctrl+D exits cleanly. Model work runs outside raw mode. Ordinary task text adds manually with AI off; with AI on, questions stay read-only and task/plan requests produce a preview requiring explicit approval. Existing explicit CLI commands retain their meaning.

## Ownership and throughput checkpoint

1. Blocking first steps. Read the pinned fx/Codex sources and Zig 0.15.2 docs, inspect existing dispatch/storage behavior, and record failure scenarios before implementation.
2. Independent workstreams. One owner changes the terminal renderer and main integration. Other owners supply the optional voice helper, sync client, and cloud service in separate files. Parent ownership prevents concurrent edits to main.zig.
3. Shared mutable state. Editor owns at most 100 history entries, an 8 KiB draft, and any input byte retained across resize. Raw terminal state exists only during an editor read and restores before model, auth, sync, and voice operations.
4. Smallest safe decomposition. Keep the existing storage/command functions and add one native terminal module. Avoid a second UI framework or the full fx/Codex agent engine.

Model the Domain shaped the Editor structure, which owns history and pending drafts instead of spreading them through command handlers. Laziness Protocol kept existing command and storage logic, removed the old input loop, and used libc allocation for the small editable buffer. The parent assigned this implementation lane; it owns provider routing and review, so this child did not launch another model or write an independent competing implementation.

## Runtime behavior and limits

The composer supports horizontal scrolling with a left marker, UTF-8 code-point editing, common combining-character/CJK/emoji widths, command completion, history with draft restoration, and bracketed paste. Width changes retain the draft and print a fresh task board. The terminal keeps previous output in normal scrollback.

Terminals below 24 columns use a plain prompt. NO_COLOR and TERM=dumb also disable terminal styling and use canonical input. Full Unicode grapheme segmentation is outside this compact renderer; editing operates on valid code points. Body text uses the terminal's foreground. The renderer strips ANSI cursor commands and OSC metadata from document/model text.

The optional /voice helper runs in canonical mode and supplies an editable draft. Its executable comes from DOIN_VOICE_COMMAND or ~/.local/bin/doin-voice. It cannot save or execute its transcript. The separate voice acceptance tests establish helper behavior; real microphone acceptance requires the operating-system permission and a real recording.

The PTY restoration check compares input/output flags, speeds, and control characters. On macOS it records but excludes PENDIN from durable equality because `man 4 termios` defines that bit as pending-input state set by the kernel during canonical-mode changes. ICANON, ECHO, ISIG, and other settings remain checked.

## Model picker implementation contract

Failure scenarios: cached catalog may belong to a stale account/provider; filter text may be mistaken for a selected slug; malformed provider names may inject terminal control codes; arrow navigation may select a hidden option; Tab may discard a prior field; Escape or resize may save partial configuration; unsupported hosted window/effort may be presented as working controls; Ollama values may be advertised but never sent; capability fetch may fail or return malformed limits. E2E will select from a realistic local catalog, filter and navigate, inspect advertised context/thinking choices, cancel without mutation, then commit and verify the next inference request contains actual supported settings. Plain mode and resize remain covered.

A focused typed picker stores field choice separately from typed filter text. Parsing placeholder text would blur display labels, search input and submitted values; immutable options plus selected field values keep that distinction explicit. Main owns bounded catalog/capability fetching and atomic configuration writes outside raw mode. The terminal module owns filtering, arrow navigation, Tab/Shift+Tab and rendering. Window/effort remain provider-managed defaults unless the provider advertises actual controls.

Primary guidance: [Ollama chat](https://docs.ollama.com/api/chat) and [official OpenAPI](https://github.com/ollama/ollama/blob/main/docs/openapi.yaml) define options.num_ctx and /api/show thinking.values/default; [OpenAI reasoning](https://developers.openai.com/api/docs/guides/reasoning) makes reasoning support model-specific. The direct ChatGPT OAuth catalog guarantees display_name/slug, not arbitrary context settings.

Model picker checkpoint 0.2.1:337000 bytes, nine PTY groups plus five core and eight auth groups passed. Dropdown and active placeholders remain neutral gray. Enter saves after the effort field; Tab cycles all fields, Shift+Tab returns, Escape cancels, and pasted delimiters cannot accept choices. Options redraw only when input changes, catalogs/capability fetches are bounded to ten seconds outside raw mode, and selected capability options cache within the invocation. /provider retains provider onboarding. Compatible API /models uses data[], direct ChatGPT catalog uses models[], Ollama uses names from /api/tags and discovered /api/show values. Capability discovery failure limits choices to genuine provider defaults; catalog failure permits a clearly labeled custom model name. No hosted context slider or invented effort options are supplied. Final picker screenshots: model-picker-models.png and model-picker-effort.png. This verified checkpoint was atomically installed to ~/.local/bin/doin.

## Persistent footer failure census and design

A normal-screen DECSTBM output region plus four reserved footer rows is chosen over an alternate-screen transcript renderer. It keeps command output, nested prompts and onboarding in the existing synchronous flow, with absolute CUP footer painting and a temporarily nine-row model popup. Native scrollback behavior for a reduced scroll region depends on the terminal emulator; no alternate screen or scrollback-clearing command is used. Margin reset and termios restoration are required on every session exit. Primary protocol reference: [xterm control sequences](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html); implementation uses Zig 0.15.2 std.posix.

Failures to cover before implementation: sparse onboarding or empty state can leave input near the top; long task, AI or help output can scroll into the composer; nested prompts can save the wrong cursor; popup expansion can overwrite transcript/footer; height-only or width resize can leave stale margins or discard a draft; short terminals, pipes, NO_COLOR and dumb mode must remain plain. Ctrl+C, Ctrl+D, SIGTERM, provider failure and picker cancellation must restore raw mode, bracketed paste, cursor visibility and full margins. Empty-state art can erase existing notes, headers or transcript, spam newlines, keep moving during typing or imply model loading. Original neutral ASCII art will update in place at roughly five frames per second only before first interaction and only with genuinely empty/default-heading content. DOIN_NO_ANIMATION=1 disables motion; small/plain terminals omit it. Tests will render the actual PTY scroll-region screen and capture both idle frames and typing/processing/footer rows.

Persistent-footer checkpoint 0.2.2: native 422488 bytes, SHA-256 `4d0509e41c97cd71060cc19e85363ecc1eb0cf6a2c005635d4fe0005ca211320`. Seventeen real PTY groups, five core CLI groups and eight auth groups pass on this exact binary. Actual screen artifacts include `onboarding-bottom-composer.png`, `empty-orbit-frame-one.png`, `empty-orbit-frame-two.png`, `processing-fixed-footer.png`, `email-poll-fixed-footer.png`, `many-groups-chart-footer.png`, `height-only-resize-footer.png` and `small-to-large-footer.png`. Complete header/path/count remain above original 25×11 neutral orbit; notes-only documents omit art. Typing clears art and stops animation. `DOIN_NO_ANIMATION=1` retains a static poster. Four bottom rows remain reserved during processing; model selection temporarily reserves nine. Output scrolls only above the footer. Small/plain terminals use canonical text input; expanding again restores docking at the next read.

Session-level signal cleanup uses fixed libc writes/termios calls and atomically tracked direct curl PID termination; main, auth and sync reap the exact owned child, and persistent cancellation prevents further prompts or AI append confirmation. OAuth callback waits check cancellation every 100ms. Slow real loopback provider and email-poll PTY scenarios verify immediate full-margin restoration, no task writes, normal terminal flags and no surviving curl. Native scrollback retention with DECSTBM remains terminal-dependent, as documented above. No alternate-screen or whole-screen erase is emitted.

TUI tests now install an exec-only curl guard accepting loopback addresses; a denied nonfixture URL probe returns before any request, and the final boundary assertion rejects any application attempt to leave the fixture. During earlier development a misconfigured email fixture reached the default hosted endpoint with an unverified reserved test email; it did not verify/sign in, obtain a token, create Checkout or alter tasks. The corrected fixture uses explicit loopback endpoint and waits for actual poll arrival before cancellation.
